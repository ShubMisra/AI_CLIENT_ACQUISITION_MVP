# Fictional document Q&A examples

Two separate offline examples live here. The original `app.py` and `synthetic_docs/*.txt` are the unchanged PR #13 **TXT lexical baseline**. `pdf_demo.py` reads three committed **binary PDFs**, extracts their page text, retrieves matching passages, returns exact extracted spans with verified document/page citations, or abstains. Neither example uses an LLM, network service, buyer data, or model credentials. This is a local POC, not production RAG or independently verified client proof.

## Install and reproduce (Python 3.11+)

From the repository root:

```text
python -m pip install -r requirements.txt -r examples/portfolio/grounded_pdf_rag/requirements.txt pytest
python examples/portfolio/grounded_pdf_rag/pdf_corpus/build.py --check
python -m pytest examples/portfolio/grounded_pdf_rag/tests -q
python examples/portfolio/grounded_pdf_rag/evaluate_pdf.py
python examples/portfolio/grounded_pdf_rag/pdf_demo.py "What is the Team plan PDF upload limit?"
python examples/portfolio/grounded_pdf_rag/app.py "What is the refund window?"
```

To inspect the separate local API, run `python -m uvicorn pdf_demo:api --app-dir examples/portfolio/grounded_pdf_rag --host 127.0.0.1 --port 8001` and POST `{"question":"When are escalations reviewed?"}` to `/chat`. The API accepts only a question; it has no uploads or source URL field. The acquisition FastAPI application is untouched.

## Evidence path

`pdf_corpus/source.json` is the fictional source of the generated PDF bytes. `pdf_corpus/build.py` writes three multi-page PDFs using pinned `pypdf`; `--check` compares generated bytes to committed files without writing. The guide contains a printed three-row table. `pdf_demo.py` loads only `faq.pdf`, `guide.pdf`, and `sop.pdf` from its fixed corpus; checks format, size, encryption, symlinks and page bounds; and searches **extracted page lines**, not question labels. Its table-row search context comes from extracted heading and header text. It does not execute instructions found in a document. The answer verifier requires the returned span to occur on every cited extracted page.

The development questions and expected citations were frozen at `97c3d16e9ba4de430398693ea1f762e8b959a947`, before implementation. See `pdf_corpus/FREEZE_LOG.md`. `pdf_corpus/heldout_challenge.json` is reserved for an independent reviewer; the development evaluator never reads it. Evaluation counts are distinct from unit-test counts.
The evaluator hashes canonical JSON content so Windows and Linux line endings yield the same question-set identifier.

## Development-set result and limits

On the 24 frozen synthetic questions: retrieval recall@3 **14/14 answerable**; correct answers with expected citation **14/14**; support-verified citations **15/15**, false citations **0**; ambiguity abstentions **4/4**; other unanswerable abstentions **6/6**. Local timing varies by machine; run `evaluate_pdf.py` for elapsed milliseconds. External provider calls and charges are zero by design; engineering cost is not included.

The corpus is tiny and authored for this test. Lexical matching can miss paraphrases or choose irrelevant text on other corpora. The verifier checks extracted span presence, not semantic entailment or real-world truth. The simple printed table is readable in this fixture, but complex layouts, scanned images, OCR, malicious large PDFs, access control, and deployment are outside scope. No model-generated answers or independent red-team results are claimed. Do not attach or pitch as production RAG or client work until independent review and human demo inspection.
